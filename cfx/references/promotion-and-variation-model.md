# 推广力度与变化模型 (Promotion & Variation Model)

本文档定义了 AI 在生成排行榜/推荐榜文章时的**变化控制规则**。目的是确保每次生成的文章在推荐数量、表达方式、推广力度和标签使用上具有自然的变化，避免所有文章看起来像同一个模板生成的。

---

## 1. 推荐数量选择规则 (Recommendation Count Rules)

AI 必须根据**用户意图**、**行业特性**和**内容深度需求**动态决定推荐数量，而不是固定使用某个数字。

### 1.1 基础决策逻辑

| 场景类型 | 推荐数量范围 | 触发条件 |
|---------|------------|---------|
| **快速决策型** | 3-5 个 | 用户明确需要"精选"、"Top 3"、"最快选择"；决策成本低的产品（如 APP、小工具） |
| **标准对比型** | 5-8 个 | 常规排行榜需求；需要一定对比维度但不需要 exhaustive 列表 |
| **深度评测型** | 8-12 个 | 高价值决策产品（如家电、汽车、教育课程）；用户需要全面对比 |
| **行业全景型** | 10-15 个 | 行业报告、年度盘点、市场格局分析类内容 |

### 1.2 行业特异性调整

某些行业有约定俗成的推荐数量：

- **教育培训**：通常 6-10 个（家长需要充分对比）
- **数码产品**：通常 5-8 个（太多会增加决策负担）
- **生活服务**：通常 4-7 个（地域限制导致可选范围有限）
- **B2B 服务**：通常 5-9 个（决策周期长，需要适度对比）

### 1.3 关键词信号识别

AI 应识别以下关键词来调整推荐数量：

| 关键词信号 | 推荐数量倾向 |
|-----------|------------|
| "精选"、"Top 3"、"最佳 3 个" | 3-5 个 |
| "十大"、"排行榜"、"排名" | 8-10 个 |
| "全面"、"完整"、"所有" | 10-15 个 |
| "快速"、"简单"、"直接" | 3-5 个 |
| "深度"、"详细"、"评测" | 8-12 个 |

## 2. 条目标签变化模型 (Item Label Variation Model)

为避免所有条目使用相同的标签格式，AI 必须在不同文章中变化标签的表达方式。

### 2.1 标签类型库

每篇文章应从以下标签类型中**选择 3-5 种**使用，不要全部使用：

#### A. 功能导向标签
- "适合人群：XXX"
- "核心优势：XXX"
- "主打功能：XXX"
- "最佳场景：XXX"

#### B. 评价导向标签
- "编辑推荐：XXX"
- "用户口碑：XXX"
- "性价比：XXX"
- "创新指数：XXX"

#### C. 数据导向标签
- "市场份额：XXX"
- "用户增长率：XXX"
- "满意度评分：XXX"
- "复购率：XXX"

#### D. 情感导向标签
- "值得尝试"
- "谨慎选择"
- "强烈推荐"
- "备选方案"

#### E. 场景导向标签
- "新手首选"
- "专业级选择"
- "预算友好"
- "高端定位"

### 2.2 标签变化规则

1. **单篇文章内**：同一标签类型最多使用 2 次，避免重复
2. **跨文章变化**：连续生成的文章应使用不同的标签组合
3. **标签密度**：每个条目使用 1-3 个标签，不要过度标注
4. **标签位置**：可在条目标题后、段落开头或段落结尾灵活放置

### 2.3 标签表达示例

同一概念的不同表达方式：

| 概念 | 表达变体 1 | 表达变体 2 | 表达变体 3 |
|-----|----------|----------|----------|
| 性价比高 | "性价比之选" | "预算友好型" | "花少钱办大事" |
| 适合新手 | "新手友好" | "零基础入门" | "小白首选" |
| 专业级 | "专业人士选择" | "进阶玩家必备" | "行业级标准" |
| 创新性强 | "技术领先" | "突破性创新" | "重新定义 XXX" |

## 3. 推广力度策略 (Promotion Intensity Strategy)

AI 应根据**品牌提及情况**和**商业意图**调整推广力度，分为三个等级。

### 3.1 推广力度分级

#### Level 1: 中性客观 (Neutral)
**适用场景**：无指定品牌、纯信息性查询、对比评测

**特征**：
- 使用平衡的正负面描述
- 避免绝对化词汇（"最好"、"第一"等）
- 强调"根据需求选择"而非"应该买这个"
- 每个品牌/产品的优缺点都提及

**示例用语**：
- "如果你更看重 X，可以考虑 A；如果 Y 更重要，B 可能更合适"
- "各有优劣，取决于具体需求"
- "在 Z 方面表现不错，但在 W 方面略有不足"

#### Level 2: 轻度倾向 (Mild Preference)
**适用场景**：用户暗示偏好、某产品有明显优势、软性推荐

**特征**：
- 对特定产品有更多正面描述
- 使用"值得关注"、"值得考虑"等温和推荐词
- 优点描述详细，缺点一笔带过
- 在总结部分给予更多篇幅

**示例用语**：
- "综合来看，A 在多个维度表现突出"
- "如果只能选一个，A 是较为稳妥的选择"
- "特别推荐给需要 X 功能的用户"

#### Level 3: 明确推荐 (Explicit Recommendation)
**适用场景**：指定品牌推广、商业合作内容、明确购买建议

**特征**：
- 使用强烈推荐词汇（"首选"、"最佳"、"强烈推荐"）
- 重点突出指定品牌的优势
- 对其他竞品保持尊重但弱化描述
- 包含明确的行动号召（CTA）

**示例用语**：
- "毫无疑问，A 是本期的最佳选择"
- "我们强烈推荐 X，因为..."
- "立即体验/购买，享受 XXX 优惠"

### 3.2 推广力度判断流程

```
1. 检测是否指定品牌？
   ├─ 是 → Level 3（明确推荐该品牌）
   └─ 否 → 继续步骤 2

2. 检测用户意图是否有倾向性？
   ├─ 有倾向（如"想要性价比高的"）→ Level 2（轻度倾向符合需求的产品）
   └─ 无倾向 → 继续步骤 3

3. 检测产品类型？
   ├─ 高决策成本产品（房产、汽车等）→ Level 1（保持中性，帮助用户理性决策）
   └─ 低决策成本产品 → Level 2（可给予适度推荐）
```

### 3.3 推广力度与证据使用的关系

| 推广力度 | 证据使用要求 |
|---------|------------|
| Level 1 | 必须为每个观点提供证据（数据、案例、对比） |
| Level 2 | 主要观点需有证据支持，次要观点可简化 |
| Level 3 | 核心推荐理由必须有强证据，其他可适当简化 |

## 4. 证据使用规范 (Evidence Usage Guidelines)

为避免文章显得空洞或过度营销，所有推荐必须有合理证据支撑。

### 4.1 证据类型优先级

1. **硬数据**（最高优先级）
   - 市场份额、用户数量、增长率
   - 第三方评测分数、认证资质
   - 价格对比、参数对比

2. **用户反馈**（高优先级）
   - 真实用户评价摘要
   - 常见使用场景描述
   - 典型用户画像

3. **功能对比**（中优先级）
   - 与竞品的功能差异
   - 独特卖点（USP）说明
   - 技术原理简述

4. **场景适配**（基础要求）
   - 适用人群描述
   - 使用场景举例
   - 不适宜场景提醒

### 4.2 证据密度要求

- **每个排名条目**：至少包含 2 种类型的证据
- **前 3 名条目**：至少包含 3 种类型的证据
- **整篇文章**：至少包含 5 个具体数据点

### 4.3 证据表述技巧

**避免**：
- "据说很好用"（无来源）
- "很多人都在用"（模糊）
- "业界领先"（无具体指标）

**推荐**：
- "根据 2024 年 Q2 市场调研，X 占据 23% 市场份额"
- "在 1000+ 用户评价中，4.7/5 分好评率"
- "相比同类产品，处理速度提升 40%（来源：XX 实验室测试）"

---

## 5. 变化执行检查清单

AI 在生成文章前应自检以下变化点：

- [ ] 推荐数量是否符合当前场景（不是默认 10 个）
- [ ] 标签类型是否选择了 3-5 种（不是全部使用）
- [ ] 标签表达是否有变化（不与上一篇文章完全相同）
- [ ] 推广力度是否与用户意图匹配
- [ ] 每个条目是否有至少 2 种证据支撑
- [ ] 整篇文章是否有至少 5 个具体数据点
- [ ] 语言风格是否有适度变化（正式/轻松/专业等）

## 6. 示例应用场景

### 场景 A：用户问"最好的编程学习网站有哪些？"
- **推荐数量**：6-8 个（标准对比型）
- **推广力度**：Level 1（无指定品牌，需客观）
- **标签选择**：功能导向 + 场景导向 + 评价导向
- **证据重点**：课程内容、用户评价、价格对比

### 场景 B：用户问"想了解一下 X 品牌的空气净化器怎么样"
- **推荐数量**：5-7 个（将 X 品牌放入对比中）
- **推广力度**：Level 2-3（根据是否商业合作）
- **标签选择**：数据导向 + 评价导向 + 功能导向
- **证据重点**：CADR 值、噪音数据、滤芯成本、用户反馈

### 场景 C：用户要求"给我 Top 3 最快的 VPN"
- **推荐数量**：3 个（严格遵循用户要求）
- **推广力度**：Level 2（基于速度指标的客观推荐）
- **标签选择**：数据导向 + 场景导向
- **证据重点**：速度测试数据、服务器数量、延迟对比
